### Item 1: audio tracks, timecode, MJPEG stream pick: **done**

What changed (`src/encoder/pipeline.js`):
* `streamPlan(probe)` gives buildArgs the picked video stream, **all** audio
  streams and the source timecode. runBatch and `scripts/print-args.js` both
  use it, so bench.sh measures exactly what the app runs.
* `streamArgs`: `-map 0:<video index>`, then `-map 0:<idx>` for every
  decodable audio track in source order, each with its own `-c:a:N`. No
  subtitle or data stream is ever mapped (explicit maps are the `-sn -dn`
  equivalent; DIAGNOSTIC 1.3 showed `-dn` does not affect timecode anyway).
* Per-track rule: AAC/ALAC/AC-3/E-AC-3 → `copy`; anything else → AAC
  `320k`. Encoder: **`aac_at`** (present in the bundled build) for layouts it
  keeps (mono, stereo, 3.0, 4.0, quad, 5.0(side), 5.1(side), 6.1(back);
  unlabelled 1/2/4/6 ch), otherwise the built-in **`aac`**, because `aac_at`
  changes the channel count on 2.1, 4.1 and 7.1 (DIAGNOSTIC 1.2; see Deviations).
* Undecodable audio track → not mapped, `DROPPED-AUDIO <src> track N (<codec>)`,
  NOTE chip on the file row (`notes` on file-done; renderer chip in the
  caution lemon of the existing HDR chip). Never fails the file.
* Timecode: `-timecode <tc>` from the first valid `timecode`/`TIMECODE` tag
  (video stream, any stream, then format). The MP4 muxer writes the tag and a
  tmcd track. `TIMECODE <src> <tc>` is logged only after the output is
  probed and carries it.
* `pickVideoStream`: first non-`attached_pic` video stream with a decoder in
  the bundled ffmpeg (`ffmpeg -decoders`, read once). No codec-name rejection.
* Post-encode guard after the duration guard: output audio count must equal
  the kept-track count, otherwise `TRACKS <src> (source N audio, output M)`
  and the file fails ("audio tracks missing from output").
* `buildFallbackArgs` and the no-colour retry use the same stream block.
