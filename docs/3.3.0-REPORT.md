### Item 1: audio tracks, timecode, MJPEG stream pick: **done**

What changed (`src/encoder/pipeline.js`):
* `streamPlan(probe)` gives buildArgs the picked video stream, **all** audio
  streams and the source timecode. runBatch and `scripts/print-args.js` both
  use it, so bench.sh measures exactly what the app runs.
* `streamArgs`: `-map 0:<video index>`, then `-map 0:<idx>` for every
  decodable audio track in source order, each with its own `-c:a:N`. No
  subtitle or data stream is ever mapped (explicit maps are the `-sn -dn`
  equivalent; DIAGNOSTIC 1.3 showed `-dn` does not affect timecode anyway).
* Per-track rule: AAC/ALAC/AC-3/E-AC-3 → `copy`; anything else → AAC
  `320k`. Encoder: **`aac_at`** (present in the bundled build) for layouts it
  keeps (mono, stereo, 3.0, 4.0, quad, 5.0(side), 5.1(side), 6.1(back);
  unlabelled 1/2/4/6 ch), otherwise the built-in **`aac`**, because `aac_at`
  changes the channel count on 2.1, 4.1 and 7.1 (DIAGNOSTIC 1.2; see Deviations).
* Undecodable audio track → not mapped, `DROPPED-AUDIO <src> track N (<codec>)`,
  NOTE chip on the file row (`notes` on file-done; renderer chip in the
  caution lemon of the existing HDR chip). Never fails the file.
* Timecode: `-timecode <tc>` from the first valid `timecode`/`TIMECODE` tag
  (video stream, any stream, then format). The MP4 muxer writes the tag and a
  tmcd track. `TIMECODE <src> <tc>` is logged only after the output is
  probed and carries it.
* `pickVideoStream`: first non-`attached_pic` video stream with a decoder in
  the bundled ffmpeg (`ffmpeg -decoders`, read once). No codec-name rejection.
* Post-encode guard after the duration guard: output audio count must equal
  the kept-track count, otherwise `TRACKS <src> (source N audio, output M)`
  and the file fails ("audio tracks missing from output").
* `buildFallbackArgs` and the no-colour retry use the same stream block.

Tests: `test/audio_tracks_test.js` (real encodes of the 7 synthetic sources

## Deviations from this prompt

1. **AAC encoder per track (item 1b).** The prompt says to use `aac_at` if
   present. It is present, but it changes the channel count on 2.1 (→ 2),
   4.1 (→ 6) and 7.1 (→ 7) (DIAGNOSTIC 1.2), which breaks "keeping channel
   count". So `aac_at` is used only for layouts measured to come through
   intact (mono, stereo, 3.0, 4.0, quad, 5.0(side), 5.1(side), 6.1(back);
   unlabelled 1/2/4/6 ch), and the built-in `aac` for every other layout. The
   built-in `aac` always keeps the count, but labels unusual layouts "unknown"
   in MP4. Every real clip went through `aac_at`.
2. **`-sn -dn` (item 1a)** are not passed literally. Explicit `-map` of the
   video stream and each audio track maps nothing else, which is the
   equivalent the prompt allows. 1.3 showed `-dn` would not have hurt timecode.
3. **`test/settings_args_test.js`** pinned the whole argv to fixtures from
   d7feacb. Item 1 changes the stream block for everyone on purpose, so the
   test now compares everything **except** that block byte for byte (all 192
   fixtures still pass), plus a new equality check of the block between the
   legacy and settings paths. The fixtures were not regenerated.
4. **Pre-change test runs.** Items 1–2 were checked against `641a837`. Items
   3–6 and 10–11 were checked against `248868f` (the item-2 commit), not each
   item's immediate parent: none of those items depends on the others, so
   `248868f` is "before the change" for each. Item 7's bench test was checked
   against `248868f` with its old `bench.sh`.
5. **10-bit → 8-bit toggle (item 2).** A consequence, not a new feature: the
   Nerd Mode option now also appears for 12-bit batches, because their output
   is now 10-bit. README/site wording changed from "a 10-bit file" to "a file
   deeper than 8 bits (10- or 12-bit)".
6. **HDR chip wording (item 3)** is mine: chip text "Dolby Vision", tooltip
   "Dropped: … Kept: HDR color tags and HDR10 brightness metadata."
7. **Recovered leftovers (item 4)** are renamed in place to their recorded
   final name. The interrupted run's folder is not flattened (see decisions).
8. **CHANGELOG heading** is `## 3.3.0 — unreleased`. The release date is yours to set.
9. **Item 7 timing.** The sweep ran in a separate worktree (code = item-2
   commit + item 7's bench.sh) while items 3–4 were tested, so its first
   wall-clock figures were inflated. Sizes and scores are unaffected. The
   published table uses a rerun with nothing else running (see Measurements).
10. **Item 8 hook vs built-in.** electron-builder 26 also has a built-in
    `electronFuses` option. I used the afterPack hook with `@electron/fuses`
    because the prompt asked for it, and made `@electron/fuses` an explicit
    devDependency.
11. **Item 11 tooltip** is the prompt's wording verbatim, though the
    behaviour is narrower (see decision 4).
12. **Item 12 docs touch-ups** (the Drop step wording and the CHANGELOG
    paragraph fix) are in the item 12 commit, not in items 5 and 8.
13. **Phase 0.2 clip count:** 13 real clips were found and cloned. The sweep
    (7b) used the ten camera clips plus the demo master, as specified. The
    62 s Sony and `IMG_0122.mov` were used for the item 1 audio/timecode
    checks only.
